# Swarm riders and Swarm-native companies

Matt Huang argues that even among highly AI-native people, AI use is power-law distributed. A new class — “swarm riders” — can consistently command large swarms of agents toward productive ends. That is a managerial skill analogous to running a large organization of people, but more technical. Based on swarm riders at Tempo and Paradigm, their productive token spend is 1,000x–10,000x a median software engineer and about 100x a top 5% Claude Code user. The craft is closer to machine learning than to ordinary software engineering: defining reward functions and evals, turning non-verifiable problems into verifiable ones, and running experiments on black-box systems. Swarm-native companies are founded and staffed by these people and organized around swarms; ordinary companies will struggle to copy that, because internal human coordination is sand in the gears. Examples he has seen up close: Tempo reshaping financial rails, Spawn building a gaming platform, and Cathedral Systems running cyber swarms. He asks how fast swarm riding will spread (and what that means for token spend), whether existing companies can adopt it or it will mostly show up in new firms, and what stays scarce once swarming itself is built into models and harnesses — his guess is cultures that define reward functions well and then get out of the way.

**Why it matters:** A clear name and frame for the leap from using one coding agent to running large agent fleets, written by someone watching it happen at Tempo and Paradigm.

**What to try:** Notice whether your own setup is still one-agent-at-a-time or already swarm-shaped; if you scale up, spend the effort on reward functions and evals rather than more coordination meetings.
